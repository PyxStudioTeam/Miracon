# Настройка почты и автоответа для заявок MIRACON

Сайт сохраняет принятую заявку и задания отправки в PostgreSQL одной транзакцией. HTTP `201` означает сохранение, **не** доставку письма. Почта отправляется отдельным Cron-процессом; без SMTP и расписания заявки остаются доступными администратору, но письма не поступают. Для уже сохранённых заявок до установки миграции задания задним числом не создаются.

Перед включением отправки: сделайте резервную копию, примените `npm run postgres:migrate` (включая `0020_contact_mail_outbox.sql`), настройте защищённые серверные переменные и Cron, затем проверьте два контролируемых адреса для уведомления и автоответа. Не отправляйте пробные письма посетителям.

**Безопасность действующего сайта:** SMTP-пароль и `CONTACT_DIGEST_SECRET` обнаружены в публичной `.htaccess`. Оператор cPanel должен сначала задать текущие значения в защищённом окружении, проверить приоритет переменных, затем удалить **только строки с секретами** из `.htaccess`, сохранив маршрутизацию Passenger, перезапустить приложение и проверить форму и Cron. После этого сменить оба секрета в защищённом окружении и снова проверить работу. HTTP 403 на `.htaccess` не доказывает безопасность. FTP к `public_html` не позволяет создать защищённое окружение; не удаляйте действующие значения вслепую.

## 1. Переменные окружения

| Переменная | Требование |
|---|---|
| `CONTACT_SMTP_ENABLED` | Строго `true` для worker; без неё `--apply` не выполняет отправку. |
| `CONTACT_SMTP_HOST` | Имя исходящего SMTP-сервера, соответствующее его TLS-сертификату. |
| `CONTACT_SMTP_PORT` | `465` (TLS) или `587` (обязательный STARTTLS). |
| `CONTACT_SMTP_USER` | Логин SMTP. |
| `CONTACT_SMTP_PASSWORD` | Пароль SMTP / отдельный пароль приложения. |
| `CONTACT_SMTP_FROM` | Почтовый адрес отправителя; принимать ответы должен обслуживаемый ящик. |
| `CONTACT_SMTP_TO` | Один внутренний адрес для уведомлений о новых заявках. |
| `CONTACT_AUTOREPLY_ENABLED` | Необязательная опция: `true` разрешает автоответ; по умолчанию выключен. |
| `DATABASE_URL` | PostgreSQL для сайта и Cron; хранить вне публичного каталога. |
| `CONTACT_DIGEST_SECRET` | Не менее 32 символов для защиты формы; хранить вне публичного каталога. |

Не используйте префикс `PUBLIC_` для секретов и не сохраняйте значения в `.htaccess`, репозитории, каталоге релиза, командной строке Cron или логах. Переменные для веб-процесса **не гарантированно наследуются Cron**: настройте безопасную передачу отдельно. Проверьте доменные SPF, DKIM и DMARC у фактического почтового провайдера.

## 2. Примеры настроек для почтовых провайдеров

### Вариант 1: Корпоративная почта на хостинге сайта (cPanel / Webmail miracon.gr) — *Рекомендуемый*
Если почта создана на том же хостинге, где делегирован домен `miracon.gr` (в cPanel раздел **Email Accounts** -> `info@miracon.gr`):

```dotenv
CONTACT_SMTP_ENABLED=true
CONTACT_SMTP_HOST=mail.miracon.gr
CONTACT_SMTP_PORT=465
CONTACT_SMTP_USER=info@miracon.gr
CONTACT_SMTP_PASSWORD=Ваш_Пароль_От_Почтового_Ящика
CONTACT_SMTP_FROM=info@miracon.gr
CONTACT_SMTP_TO=info@miracon.gr
```
*(Если используется порт `587`, укажите `CONTACT_SMTP_PORT=587`).*

---

### Вариант 2: Google Workspace или личный ящик Gmail (@gmail.com)
Google требует обязательную двухфакторную аутентификацию (2FA) и специальный **Пароль приложения** (обычный пароль от аккаунта Google отклонит):

1. Перейдите в аккаунт Google: **Безопасность** -> **Двухэтапная аутентификация** (включите, если выключена).
2. В самом низу раздела найдите **Пароли приложений** (App Passwords).
3. Создайте пароль с названием, например, `Miracon Website`, скопируйте сгенерированный 16-значный код (без пробелов).
4. Пропишите переменные:

```dotenv
CONTACT_SMTP_ENABLED=true
CONTACT_SMTP_HOST=smtp.gmail.com
CONTACT_SMTP_PORT=465
CONTACT_SMTP_USER=ваша_почта@gmail.com
CONTACT_SMTP_PASSWORD=шестнадцатизначный_код_приложения
CONTACT_SMTP_FROM=ваша_почта@gmail.com
CONTACT_SMTP_TO=куда_присылать_заявки@miracon.gr
```

---

### Вариант 3: Яндекс 360 / Яндекс Почта (@yandex.ru / на домене)
Для Яндекса также требуется «Пароль приложения»:
1. Перейдите в **Яндекс ID** -> **Безопасность** -> **Пароли приложений**.
2. Создайте пароль для типа «Почта».
3. Пропишите переменные:

```dotenv
CONTACT_SMTP_ENABLED=true
CONTACT_SMTP_HOST=smtp.yandex.ru
CONTACT_SMTP_PORT=465
CONTACT_SMTP_USER=info@miracon.gr
CONTACT_SMTP_PASSWORD=пароль_приложения_яндекс
CONTACT_SMTP_FROM=info@miracon.gr
CONTACT_SMTP_TO=info@miracon.gr
```

---

### Вариант 4: Zoho Mail
```dotenv
CONTACT_SMTP_ENABLED=true
CONTACT_SMTP_HOST=smtppro.zoho.eu
CONTACT_SMTP_PORT=465
CONTACT_SMTP_USER=info@miracon.gr
CONTACT_SMTP_PASSWORD=пароль_или_app_password
CONTACT_SMTP_FROM=info@miracon.gr
CONTACT_SMTP_TO=info@miracon.gr
```
*(Для серверов в регионе США хост — `smtp.zoho.com`).*

## 3. Развёртывание на cPanel

1. В **Setup Node.js App** поместите переменные сайта в защищённую конфигурацию Passenger вне `public_html` и каталога релиза. Создайте отдельный источник переменных Cron с правами `0600` вне этих каталогов или используйте защищённое окружение хостинга; убедитесь, что обе среды содержат актуальные значения. Не кладите `.env` рядом с `app.js` в развёрнутый релиз.
2. Примените миграции `npm run postgres:migrate` перед запуском нового приложения и worker. Установите production-зависимости (`npm ci --omit=dev`) для целевого Node 22; перезапустите Passenger и проверьте `GET /api/health`.
3. Выполните из текущего релиза `npm run contact:mail:drain` без `--apply`: это сухой просмотр количества заданий без SMTP-отправки. Настройте минутный Cron `node scripts/contact-mail-drain.mjs --apply` с абсолютными путями к Node и релизу, отдельным `flock`, закрытым логом и уведомлением об ошибочном коде завершения. Не рассчитывайте на `PATH` или переменные интерактивной оболочки в Cron.
4. Проверьте сначала внутренний ящик на одной контролируемой заявке. Для автоответа установите `CONTACT_AUTOREPLY_ENABLED=true`, перезапустите приложение, отправьте одну EN и одну EL заявку на **свой** адрес и запустите worker; после успешной проверки разрешайте опцию для посетителей. Оставляйте возможность ответить на `CONTACT_SMTP_FROM` живому менеджеру.
5. После переключения и проверки работы формы и worker смените оба ранее публичных секрета в защищённой конфигурации и повторите проверку. Используйте контрольный список в `docs/production-release-runbook.md`.

## 4. Состав писем и гарантии доставки

Уведомление приходит на `CONTACT_SMTP_TO`: ID заявки, время приёма, язык, источник, имя, контактные данные и сообщение. `Reply-To` указывает на проверенный email посетителя при его наличии. Сырые IP-адреса, защитные хеши и SMTP-секреты не включаются в письмо.

Автоответ ставится в очередь только после приёма заявки с согласием и корректным email, если `CONTACT_AUTOREPLY_ENABLED=true`. Текст на английском или греческом кратко подтверждает получение; ни сообщение, ни телефон, ни персональные данные заявителя не дублируются. На один email без учёта регистра отправляется не более одного автоответа в скользящие 24 часа.

Worker арендует задания из `miracon.contact_mail_jobs`, при ошибках делает до десяти попыток с задержкой от минуты до часа. Просроченные автоответы после 24 часов и внутренние уведомления после семи дней переходят в `dead`; не отправляйте их вручную посетителям без проверки. Перезапуск worker после принятия SMTP, но до записи результата, может дать повторное письмо: гарантируется **at-least-once**, не exactly-once. Ответ сайта не зависит от доступности SMTP.

Наблюдайте за кодом завершения Cron, числом просроченных `queued`/`dead`, категориями ошибок и задержкой доставки. Логи не должны содержать персональные данные, текст заявки, пароли и сообщения SMTP-провайдера. Проверьте папку «Спам» и записи SPF/DKIM/DMARC. Ошибки авторизации устраняйте в защищённых настройках, а ошибки TLS — корректным именем и сертификатом сервера, **не** отключением проверки сертификата.

## 5. Проверка ранее накопленных заявок

Заявки, принятые до установки этой миграции, остаются в `miracon.contact_submissions` и доступны в защищённом интерфейсе администратора и CSV-экспорте. Старые письма автоматически не создаются. Если нужно сверить очередь после миграции, оператор выполняет SQL через защищённое подключение, не на публичном сайте:

```sql
SELECT kind, state, count(*)
FROM miracon.contact_mail_jobs
GROUP BY kind, state
ORDER BY kind, state;
```

## 6. Диагностика

| Симптом / Ошибка | Причина | Способ решения |
|---|---|---|
| **Invalid login / 535 Authentication failed** | Неверный логин/пароль или почтовый провайдер требует пароль приложения. | Проверьте `CONTACT_SMTP_USER` и `CONTACT_SMTP_PASSWORD`. Для Gmail, Яндекс, Mail.ru создайте отдельный «Пароль приложения» в настройках безопасности аккаунта. |
| **Connection timed out (ETIMEDOUT)** на порту 465 / 587 | Хостинг блокирует исходящие SMTP-соединения на уровне файрвола. | На некоторых shared-хостингах исходящий SMTP во внешний мир закрыт по умолчанию. Напишите в техподдержку хостинга: *«Прошу открыть исходящие SMTP-порты 465 и 587 для подключения к внешним почтовым серверам»*. |
| **Self-signed certificate in certificate chain** | Почтовый сервер использует самоподписанный SSL-сертификат. | Приложение требует валидный TLS-сертификат (`rejectUnauthorized: true`). Если используется корпоративная почта cPanel, убедитесь, что в качестве `CONTACT_SMTP_HOST` указан хост с установленным Let's Encrypt / cPanel SSL (например, имя сервера хостинга `serverXX.hosting.com`). |
| **Письма попадают в «Спам»** | Отсутствуют или неправильно настроены SPF, DKIM или DMARC. | Настройте записи для *фактического* провайдера и домена отправителя по его документации; не копируйте чужой `include:` или политик DMARC. |
| **Форма выдаёт ошибку при отправке** | Отсутствует `CONTACT_DIGEST_SECRET` или его длина менее 32 символов. | Задайте случайный серверный секрет вне публичного каталога и перезапустите приложение. |
| **Заявка сохранена, письма нет** | Worker не запущен, неверное SMTP-окружение Cron или задания в состоянии `dead`. | Проверьте сухой прогон `npm run contact:mail:drain`, защищённую конфигурацию Cron, закрытый лог и состояния очереди. |
